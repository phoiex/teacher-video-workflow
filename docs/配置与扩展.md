# 配置与扩展

## 模型分工

`models.json` 包含 `planner`、`writer`、`editor`、`producer` 四个角色，分别负责规划、讲稿初稿、去 AI 味改写和画面制作。默认均为 DeepSeek。

推荐 Gemini 负责 `writer` 和 `editor`，Claude 负责 `producer`：先写完整稿，再独立修改表达，讲稿确认后制作分镜和视频。使用这套分工需要配置对应的 API 凭据、模型名称和协议；随包示例保留已验证的 DeepSeek 配置。

每个角色填写 `provider`、`model`、`protocol`，按模型需要填写 `reasoning_effort`。服务商可以是 `deepseek`、`openai`、`anthropic` 或 `custom`；相应 API 地址和密钥放在 `.env`。

```json
{
  "provider": "openai",
  "model": "填写实际可用的模型名",
  "protocol": "responses"
}
```

把这个配置替换到所需角色，其他角色保留。新课程创建时会保存完整模型分工；修改默认配置会用于之后的新课程。Dify 的 `COURSE_MODELS` 环境变量也可填写完整的四角色 JSON，覆盖本地默认值。

文字节点支持 `responses`、`chat.completions`、`messages`。制作执行器使用 Codex SDK，接收 Responses 协议；其余协议经本机 LiteLLM 适配，需要安装：

```sh
.venv/bin/python -m pip install -r requirements-adapter.txt
```

Messages 模型通过 `catalog_model` 关联 LiteLLM 中的模型资料，用于取得该模型要求的输出参数。换模型后先用短稿检查工具调用和图像输入。当前已验证的完整单镜头路径为 DeepSeek；其他服务商的制作效果需要单独测试。

配音使用百炼北京地域的 `SpeechSynthesizer` 接口、`longanlingxin` 音色、24 kHz 单声道 WAV。更换语音接口时修改 `teacher_flow/tts_client.py`；语速和语气由老师在课程要求中填写。

## 修改讲法、风格和节点

- `teacher_flow/prompts.py`：需求整理、教学安排、写稿和改写的提示词。
- `teacher_flow/instructions/`：制作工具说明与分镜任务。
- `skills/deslop-zh/`：中文表达规则。
- `skills/explainer-video-production/branches/`：三种画面分支。
- `teacher_flow/styles.py`、`assets/style/`：预设名称、分支与参考图的对应关系。

新增风格时，补充 Skill 分支和参考图，同时更新 Dify 开始节点、需求确认节点的选项，以及 `dify-overlay/web/app/components/workflow/run/style-preview-options.tsx`。随后重新构建前端并发布工作流。

制作工具暴露 `course_read`、`course_plan`、`course_scene`、`course_write`、`course_render`、`view_image` 和 `course_review`。模型可读本课材料、保存 HTML 和查看实际渲染结果。每段页面实现 `window.film.frame(t)`，按时间重建画面。

## Dify 改动

Dify 固定版本和改动文件清单在 `dify-base.json`。`dify-overlay/` 保存改动后的文件，安装时覆盖到对应版本；主要涉及审核弹窗、实时进度、风格预览和绑定原发布版本的断点重试。

Dify 原生发布、节点编辑和测试入口继续使用。课程生成节点目前通过 HTTP 调用本地工具，模型配置在上述角色文件中；需要原生 LLM 节点时，可在编辑器中新增节点并接入自己的数据契约。

## 本地检查

```sh
.venv/bin/python -m unittest discover -s teacher_flow -t . -p 'test_*.py'
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
node --test teacher_flow/test_production_panel.mjs teacher_flow/test_storyboard_panel.mjs
.venv/bin/python scripts/check_public.py
```

这些检查使用固定数据。前端与 Dify 后端的相关测试保留在 `dify-overlay/`，合入固定版本源码后可按 Dify 的测试命令运行。
