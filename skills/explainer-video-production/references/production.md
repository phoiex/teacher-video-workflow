# 制作流程与复用

在新建工程、选择渲染路线或修改时序机制时读取。已有稳定项目只取需要的部分。

## 把口述转成可见动作

分镜的工作单位是一个解释动作，而非每句配一张新幻灯片。用简表记录片段标识、口述、主对象、变化、观察结论和时间依据即可。顺序由讲解决定，不固定六段或十段。

例如“这个词的表示会随语境变化”：保留同一个词卡，先呈现两句不同语境，再显示语境处理后的表示差异；只改变当前要解释的关系。持续换背景、跳字或故障噪声不能代替这个动作。

讲解要指到具体对象。“这条线”“这里的数”必须有对应的指示；标签在对象运动时维持关联。几何的遮挡、虚线、交点和相等关系按真实几何处理。示意数值与实测结果区分，虚构概率或损失曲线不得冒充模型运行。

## 选择工具

| 已有条件 | 做法 |
|---|---|
| 上一课已有稳定工程和导出 | 先复用文字、布局、音频、时间轴、缓存和导出；新增本课场景 |
| 需要 HTML 场景、时间轴和可视编辑 | 可考虑 OpenFilm；按当前版本官方手册接入，不凭旧命令猜接口 |
| 已有 React/Remotion 工程 | 可借鉴 MotionCraft 的配置与组件；沿用 Remotion 渲染机制 |
| 参考是 ASCII/CRT 音乐片 | 取其统一时间、逐段编舞与反馈方法；它当前公开的终端播放器不等于通用 MP4 工具 |

选一个主要实现路线。OpenFilm 页面和 Remotion 组件不能直接互换；迁移视觉原则容易，迁移运行代码需要适配。只有复用路线明显无法承载当前画面，才补一个必要模块，避免每课重新实现字体解析、字幕引擎和导出器。

## 时间与可重建画面

用已确认配音决定正式时间轴。记录每段实际时长，明确全片时间和局部时间的换算。字幕、指示、高亮和转场共享这份时间依据；若需要关键词级动作，取实际时间戳并核对，不能仅按字符长度分配。

场景尽量实现成“给定 t，得到这一刻完整画面”。随机散布用固定种子，缓存可重建的中间结果；避免依赖上一帧不断累加的位置或真实系统时间。音乐节拍只用于需要它的段落，普通讲解无需套用参考 MV 的 BPM。

OpenFilm 的对应机制是 `film.html` 安排片段，页面提供 `window.film.frame(t)`，主机任意取时刻画面；声明为可编辑的标题/标注优先使用 DOM，Canvas/WebGL 内的文字通常仍需通过代码修改。其 `look` 是抽样和乱序重绘检查，不能代表全片质量通过。[协议](https://github.com/openfilm/openfilm/blob/604fc14e10aac027218f08e4ba79a8567d42d00d/packages/openfilm/SPEC.md#L149-L176)

## 检查、修改与接续

先看代表性实际画面：中文长句、最密标签、复杂空间关系、字幕与主体的边界，以及进入/停留/退出时刻。若单张关键帧好看，仍需看短段，检查过程中的遮挡和变化是否连贯。

按问题分类修改：事实或逻辑、对象/标注、版式、动作/时序、声音、导出。先改影响理解的原因。修改可复用组件后，检查全片同类位置；只改文字则不必重渲染不相关的昂贵 3D。

分块完成标记必须与源文件、输入素材和渲染参数相匹配。中断后检查状态文件及输出，接着渲染未完成或失效部分。保留最近有效结果，避免把新输出直接覆盖成唯一副本。

最终检查实际成片的主要知识点、字幕、音轨、转场和文件完整性。完整解码能发现文件损坏，抽帧能发现部分布局问题，二者都不能证明推理正确或观众已经听懂。交付说明写实际做过的检查。

## 本流程从哪里来

- ASCII 项目公开多轮需求，包含局部截图反馈、恢复先前设计与同类问题检查；当前音频时钟驱动画面。吸收方法，不复制歌词/歌曲/未明确授权的场景代码。[提示词](https://github.com/yym8224961/world.execute-me-ascii/blob/3409cf081e36fc57bc8fda76c54a4fc9986e8441/docs/prompts/creation-prompts.md)
- OpenFilm 提供通用时间轴与渲染；one-prompt 借用 pdoom-video 引擎，再制作专属场景。吸收确定性时间接口、复用底座和实际预览，不把片名当作一次生成证据。[引擎继承](https://github.com/openfilm/examples/blob/2e8f47866bc2d32305cd5d97adcffd7480df2297/one-prompt/src/px/README.md)
