# 分支三：OpenFilm／代码动画科技

适合字体、几何、三维、粒子、灯光和镜头共同参与的代码动画。参考 one-prompt 的具体影片系统，以及 OpenFilm 的编辑/渲染流程；不把 OpenFilm 本身定义成一种固定配色。

固定来源：OpenFilm `604fc14e10aac027218f08e4ba79a8567d42d00d`；examples `2e8f47866bc2d32305cd5d97adcffd7480df2297`。one-prompt 的原始生成对话和调用顺序未公开，下文区分官方工作流与源码可确认的制作依赖。

## 原项目的工作流与实现

OpenFilm官方Agent提示词给出的流程是：理解需求与资料 → 逐镜头规划画面/时长/声音 → 制作素材、页面与时间轴 → 实际查看输出并修正 → 交付。[公开工作流](https://github.com/openfilm/openfilm/blob/604fc14e10aac027218f08e4ba79a8567d42d00d/apps/desktop/src/agent-prompt.md#L18-L28)

one-prompt的源码实现了以下依赖链，不能将它当作作者未经编辑的操作日志：

| 阶段 | 已有文件与实现 | 下一步使用什么 |
|---|---|---|
| 音乐与时间材料 | 已生成歌曲、`lyrics.js`逐词时间、`audio.json`节拍与包络、字体和帧图集 | 镜头读取文字、发音与动作时刻 |
| 共用图形底座 | `src/px`从pdoom-video移植；绘图、字体、描边、渲染目标与后期共用 | 每个具体镜头调用共用能力 |
| 镜头实现 | `src/plates`里的专属场景、几何与shader | `timeline.js`决定镜头时间段 |
| 镜头衔接 | `handoff.js`定义切点和交接时屏幕对象 | 把场景组织成连续影片 |
| 页面与总时间轴 | 8个section页面；局部时间`t`换成歌曲时间`start+t`；`film.html`排列画面和声音 | 预览主机调用`window.film.frame(t)` |
| 预览与导出 | 修改场景后预览；`look`查看指定时刻/范围；浏览器取帧、FFmpeg编码与混音 | MP4及可编辑页面/源码 |

原片90.9秒、19个镜头时间段；这些是作品参数，不是新课模板配额。[影片组织](https://github.com/openfilm/examples/blob/2e8f47866bc2d32305cd5d97adcffd7480df2297/one-prompt/README.md#L26-L53) · [移植引擎](https://github.com/openfilm/examples/blob/2e8f47866bc2d32305cd5d97adcffd7480df2297/one-prompt/src/px/README.md) · [时间轴](https://github.com/openfilm/examples/blob/2e8f47866bc2d32305cd5d97adcffd7480df2297/one-prompt/src/plates/timeline.js)

## 采用这条分支时怎样做

本工作流使用自包含 HTML 与 `window.film.frame(t)`，通过课程工具保存、预览和导出。下列原项目方法按当前讲稿与渲染能力取用。


1. **定内容与镜头承接。** 每镜头写清主体、变化、时长依据和声音，并说明上一个镜头留下什么、下一个镜头接住什么。按内容决定二维、三维或混合，不为技术感强行全3D。
2. **复用底座与视觉规则。** 沿用可用的OpenFilm或既有工程，统一字体、线条、色板、光与后期。需要复用`px`时保留许可；具体影片场景只选与当前内容有关的部分。
3. **准备本课素材。** 生成或导入经过授权的配音/音乐；保存真实时长与词句事件。已有阿里云WAV可以作为音频素材接入，不必更换TTS服务。字体和预计算图像也属于素材，分别登记。
4. **把镜头写成时间函数。** 同一时刻能重新画出同一状态，不依赖前一帧累积。三维负责空间对象；希望手工改字的标题/标注优先DOM，避免全部画入不可逐字编辑的Canvas。
5. **组装时间轴。** 画面页、音频与字幕分开组织；记录局部/全局时间。移动切点时同步更新场景交接和时间轴，不能只拖片段却仍读取旧歌曲时刻。
6. **先验复杂短段。** 查看当前镜头、切点前后、字体与标签、字幕和声音。`look`的抽样/乱序重绘帮助发现问题，仍需看片判断运动是否清楚。
7. **分段制作与导出。** 音画通过后扩展全片，缓存对应输入版本。需要烧录字幕时显式选择对应导出方式；混音后核对声音，再交付MP4和可编辑工程。

## 这条路线的视觉重点

用共享色板与图形语言维持整体感；对象跨镜头连续交接；镜头运动揭示空间关系；灯光、粒子和后期服务主体。普通讲解按配音安排观察时间，原MV的122 BPM、歌词索引和固定镜头长度不沿用。需要柔和霓虹配色时可选读[视觉配置](../references/technical-explainer.md)，它不替代这条制作流程。

## 本分支的最小产物

镜头表、共享视觉规则、声音与事件数据、场景页面/模块、总时间轴、实际预览、修改与缓存记录、成片和可编辑工程。某项目已具备其中一部分时继续复用。

## 可转交的制作说明

> 用代码绘制具有连续镜头关系的视频。先根据内容安排每个镜头的主体、变化和声音，再建立共享视觉规则与可复用绘图组件。页面按时间重建完整画面，用统一时间轴组织场景、配音与字幕。先看复杂镜头和转场的实际输出再扩展全片，针对问题局部修改，交付视频及可编辑工程。

这是本项目整理的复用指令，非one-prompt原始用户Prompt。共用检查见[制作流程](../references/production.md)。
