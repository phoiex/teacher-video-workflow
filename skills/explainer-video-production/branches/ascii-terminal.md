# 分支二：ASCII／终端科技

适合字符网格、程序运行、数据流、终端与CRT叙事。参考 `world.execute-me-ascii`，源码固定在 `3409cf081e36fc57bc8fda76c54a4fc9986e8441`。这是独立制作路线；琥珀色终端仍属于本分支，不因色温偏暖改走暖色图解。

## 原项目怎样制作

作者公开了按需求顺序整理的25轮提示词，开头与场景注释经过编辑，未公开完整模型回复。可确认的过程是：

| 创作阶段 | 公开需求体现的动作 | 可复用方法 |
|---|---|---|
| 初始需求 | 用给定歌曲与歌词制作终端字符动画，要求双语字幕同步 | 先明确声音、文本、显示方式与同步要求 |
| 画面方向 | 修改开场初始化、减少频谱占屏、提高动画密度并保持程序风格 | 先修整体空间分配与统一视觉语言 |
| 逐段设计 | 指定时间段，重做图形、进度、节点、心电等动作；有时恢复此前版本 | 每段含义对应具体动作，改稿保留可回退版本 |
| 跨段连续性 | 调整后段故障累积、重建、计数和收尾 | 用跨段状态连接镜头，避免独立动画堆砌 |
| 局部修正 | 根据截图指出形状空洞，再找后段同类问题 | 修一个组件后检查全片复用处 |
| 交付要求 | 最后提出手机横屏MP4 | 交付目标与实际导出实现分别核实 |

依据：[创作提示词原文](https://github.com/yym8224961/world.execute-me-ascii/blob/3409cf081e36fc57bc8fda76c54a4fc9986e8441/docs/prompts/creation-prompts.md)。此处总结编辑后的需求过程，不推测每次模型调用、耗时或费用。

实际播放链路是：本地音乐 → Swift/AVAudioPlayer输出播放时刻 → Python读取时刻 → 场景路由结合歌词时间与预计算频谱 → 字符网格与ANSI颜色 → 终端显示。`scenes.py`主要按歌曲时间切换专用函数；运行时没有LLM自动选镜头。[音频时钟](https://github.com/yym8224961/world.execute-me-ascii/blob/3409cf081e36fc57bc8fda76c54a4fc9986e8441/AudioClock.swift) · [画布与播放器](https://github.com/yym8224961/world.execute-me-ascii/blob/3409cf081e36fc57bc8fda76c54a4fc9986e8441/player.py) · [场景路由](https://github.com/yym8224961/world.execute-me-ascii/blob/3409cf081e36fc57bc8fda76c54a4fc9986e8441/scenes.py#L2921-L3058)

历史版使用 cool-retro-term 和「琥珀双语」预设提供曲面/辉光；当前主分支是系统终端播放器，不自动复现那些外部效果。当前打包程序输出播放器`.pyz`；虽然需求里有MP4，公开代码未给出已核实的MP4导出链路。

## 采用这条分支时怎样做

本工作流使用自包含 HTML 与 `window.film.frame(t)`，通过课程工具保存、预览和导出。下列原项目方法按当前讲稿与渲染能力取用。


1. **先定显示与交付。** 用户需要真实可交互终端，还是终端外观的视频？需要MP4时，先决定已有离屏字符渲染器或可录制的画面输出，不把`.pyz`当成视频成品。
2. **准备新的时间数据。** 使用本课真实配音/音乐、文本时间与必要事件；无需频谱驱动时省略频谱。不要沿用旧歌的秒数或默认每段都有节拍。
3. **建立字符视觉规则。** 明确字符网格、字号/行距、色板、主动画区和字幕区。字符宽度及中文显示需要在目标尺寸检查；CRT曲面、扫描线、故障仅在选定风格需要时使用。
4. **按含义编写场景函数。** 每段接收时间与内容数据，画出完整状态。优先线、框、投影、点阵、节点、数据流等基础组件，再组合成场景。
5. **用状态连接场景。** 对象的形成、连接、断开、重组有清楚前后关系。模型原理相关画面需另核内容，不能复制原MV的虚构损失/概率作为实测。
6. **逐段预览与修正。** 结合截图或短段提出可定位修改；复用形状出错时检查所有出现位置。保留被认可的旧版本，避免每轮把全片推倒。
7. **按目标导出。** 核对音画、中文字幕、暂停/跳转及最终输出；分别交付视频和可编辑场景/时间数据。复用源码前核实授权，当前仓库未声明通用代码许可证。

## 本分支的最小产物

声音/文本、事件时间表、字符视觉配置、场景与共用绘图组件、实际短段预览、反馈与版本、目标格式输出。若只整理方案，给出这些文件的职责即可，不提前生成音频或搭建播放器。

## 可转交的制作说明

> 采用统一的终端字符视觉，用时间驱动场景状态。先建立可读的网格、主画面与字幕区域，再逐段把内容转换为节点、线、图形、重组或状态变化。保持对象和程序语言连续，预览后按具体位置修改，并复查复用组件。新声音使用新的时间数据；最终按要求交付MP4或交互播放器。

这是本项目整理的复用指令。共用制作和恢复规则见[主流程参考](../references/production.md)。
